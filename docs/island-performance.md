# 灵动岛高刷新率修复

用户的外接屏为独显直连，当前 DP-1 为 2560×1440、165Hz、125% 缩放。卡顿主要出现在灵动岛展开/收起。

## 原因与修复

Qt 6.12.0 的 [SpringAnimation 实现](https://github.com/qt/qtdeclarative/blob/v6.12.0/src/quick/util/qquickspringanimation.cpp#L180) 使用 16ms 的离散积分，并明确将弹簧模式限制在约 62 FPS。原版把该动画用于胶囊宽高及通知按钮位移，因此即使渲染器呈现更快，形状也不会逐帧更新；原参数还留下约一秒的收稳长尾。

- 宽度改为 340ms 的连续 OutBack 补间，保留轻微回弹；高度改为 300ms 的 OutCubic 补间。
- 通知按钮与媒体行的位移动画一并改为连续补间。
- 用 Qt.callLater 合并同一帧内由居中位置、宽度和高度触发的点击区域更新，减少 Python/Wayland 热路径调用。
- 保留当前显卡和屏幕配置，没有将临时 Vulkan、Mesa、渲染线程或关闭同步的实验参数加入服务。

## 实测与边界

单独运行真实 Wayland layer-shell 场景，使用独立配置和历史，按三次展开/收起采集 QML 的形状变化及应用 frameSwapped 时间（不等于屏幕实际呈现时间）。

| 指标 | 旧版单实例 | 修复后单实例 |
| --- | --- | --- |
| 形状更新间隔中位数 | 19ms | 7–9ms |
| 形状更新间隔 P95 | 61ms | 37–38ms |
| 收稳时间 | 约 0.95–1.14 秒 | 约 0.30–0.41 秒 |

中位数约相当于从 53 次/秒提升到 111–143 次/秒；这是采样中的形状更新频率，不是对持续稳定 165 FPS 的承诺。仍存在偶发长帧。

最初两个岛叠在同一位置时采到约 16 FPS，这个数值受叠层干扰，已弃用。后续采样必须暂停现有灵动岛，交还 Plasma 通知服务，只运行一个测试表面。

Vulkan、强制 threaded/basic、关闭同步、单独指定 Mesa 及其他动画驱动的对照，没有提供可保留的改善；仅加载 NVIDIA 库不等于实际渲染设备，不能据此归因于显卡。

## 复测

在 CachyOS 宿主的 dynamic-island 源码目录执行：

```bash
/usr/bin/python diagnostics/measure-animation.py --exclusive --target-fps 144 --check
```

脚本短暂把通知交回 Plasma，测试结束后恢复灵动岛。采集只使用时间和尺寸，不记录桌面内容或输入事件。`--minimal` 保留只含原弹簧动画的最小复现，可确认该动画的更新上限。

## 后续调整与测量口径

用户确认的收起速度为宽度 450ms、高度 430ms，保留 InOutCubic；展开仍为 340/300ms。上表是调整收起速度前的历史采样，不是当前版本的验收数据。

最小原生 C++ 场景同样出现长帧。软件渲染配合精确定时器虽能稳定更新属性，Wayland presentation feedback 仍出现明显长帧，因此没有部署该实验，也没有把属性更新频率当作显示帧率。当前尚未实现稳定 144 FPS。

诊断源码和可复现构建说明见 `diagnostics/README.md`，不随运行程序安装。架构拆分见 [island-architecture.md](island-architecture.md)。

## 2026-10-25 重构后复测

在 165Hz 外屏上用新版真实场景独占运行三次收放，记录 49 个动画间隔：应用 frame-ready 与形状更新 P50 均为 20ms、P95 为 67ms、最大 84ms；从触发到收稳约 374–567ms（含悬停延时）。144 FPS 检查失败。

这次结果仍有明显长帧，不能据此称重构提高了帧率。它与历史采样的运行负载和动画时长不同，未作严格成对性能比较。此次完成的是结构整理与行为回归；稳定 144 FPS 仍未解决。
